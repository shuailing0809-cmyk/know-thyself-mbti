# 反馈复核与采纳规则

## 一、固定节奏

每天按北京时间执行：

```text
00:00 归档刚结束自然日的全部用户反馈
09:00 将反馈复核日报发送给你
09:00 后 你和 Codex 一起确认哪些反馈可以被采纳
```

说明：
- “当天反馈”按北京时间自然日计算，即 00:00:00 到 23:59:59。
- 凌晨 00:00 处理的是刚结束的那一天，避免和新一天反馈混在一起。
- 09:00 发送的是上一自然日的复核清单。

## 二、反馈不会自动改规则

任何用户反馈都不能直接修改测评系统。

反馈只能先进入候选池，然后经过：

```text
自动初筛
→ 日报归档
→ 你和 Codex 人工复核
→ 转成可回放样本
→ 修改规则
→ 跑回归测试
→ 发布新版本
```

## 三、反馈分类

### 待复核

进入你和 Codex 共同确认。

典型特征：
- 指出了具体维度，例如 EI、SN、TF、JP。
- 说明了哪里一致或不准确。
- 给出了理由、例子或真实认知差异。
- 能转化成测试样本。

### 只统计

不直接进入规则调整。

典型特征：
- 有评分，但说明比较泛。
- 有感受，但没有明确维度或例子。
- 可以用于观察整体满意度，但不能作为规则依据。

### 弱反馈

只保留，不参与训练或规则修正。

典型特征：
- 只有“准 / 不准 / 一般”。
- 没有具体解释。
- 无法判断问题发生在哪个维度。

### 隔离

不进入样本池。

典型特征：
- 恶搞、灌水、攻击性内容。
- 明显诱导系统输出有害、歧视或标签化判断。
- 与测评无关。

## 四、采纳标准

一条反馈即使被标记为“待复核”，也不等于自动采纳。

真正采纳必须满足：
- 能定位到具体问题。
- 能解释为什么原判断不稳或错误。
- 能转成回归测试样本。
- 修改后不能破坏既有正确样本。

## 五、日报生成命令

生成指定日期反馈日报：

```bash
cd /Users/shuailing/Documents/Playground/mbti_agent
python3 -m app.feedback_review --date 2026-06-22 --output docs/feedback_reviews/2026-06-22.md
```

查看日报：

```bash
open docs/feedback_reviews/2026-06-22.md
```

线上部署后，可以把这个命令接入定时任务，在每天 09:00 发送给你。
